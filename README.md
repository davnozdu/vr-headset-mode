# VR Headset Mode

Модуль KernelSU / Magisk: VR-очки перестают быть монитором и становятся
обычной гарнитурой. Телефон работает как всегда, а в очки идёт только звук.

Собрано под **OnePlus 15 (Android 16, KernelSU Next)** и очки **XREAL One Pro**.

---

## Зачем

Очки по USB-C — это сразу несколько устройств: дисплей по DisplayPort,
USB-аудио с динамиками и микрофонами, HID-каналы и камера. Android
подхватывает дисплей и разворачивает на нём рабочий стол, даже когда он
не нужен: на прогулке, за музыкой или во время разговора.

Модуль гасит только видео. Всё остальное остаётся: звук, микрофоны, камера.

## Что делает

При подключении очков модуль:

1. **включает внешний дисплей** программно — это эквивалент кнопки «каст»
   в системном диалоге;
2. выдерживает паузу, пока очки поднимают аудиоусилитель;
3. **выключает картинку** через `IDisplayManager.disableConnectedDisplay`;
4. закрывает всплывший системный диалог о касте.

Итог: очки работают как обычная гарнитура — звук и микрофоны есть,
изображения нет, телефоном можно пользоваться как всегда.

## Почему именно так

Путь выбирался экспериментально, и два очевидных способа оказались негодными.

**Гасить DisplayPort нельзя.** Принудительный `disconnected` на DRM-коннекторе
убирает картинку, но прошивка очков считает потерю линка извлечением кабеля
и сбрасывает устройство целиком — вместе со звуковой картой. Замеры показали
цикл: очки отваливались и поднимались каждые 10–15 секунд.

**Гасить питание дисплея бесполезно.** `requestDisplayPower` диалога не
вызывает, но изображение продолжает гореть.

**Включение обязательно.** Без него линк не поднимается, очки не запускают
аудиоусилитель, и звука нет совсем: при отмене системного диалога звук не
появляется вовсе. Поэтому модуль сначала включает дисплей и только потом
гасит картинку.

## Настройки

`/data/adb/vr_headset/settings.conf`, читается при запуске демона,
обновлением модуля не перезаписывается:

```
READY_GRACE=1      # пауза между включением дисплея и гашением
READY_TIMEOUT=20   # сколько ждать появления дисплея
```

На XREAL One Pro секунды достаточно. Если после подключения звук иногда
не появляется — увеличьте `READY_GRACE`.

## Совместная работа с VR Display Mode

Модули дополняют друг друга, а не спорят.
[VR Display Mode](https://github.com/davnozdu/vr-display-module) включает
дисплей при подключении очков — в режиме гарнитуры это нужный первый шаг.
Дальше этот модуль гасит картинку.

Утилита `vrdisplay.dex` берётся из соседнего модуля: держать вторую копию
значило бы однажды разойтись версиями.

## Опознание очков

Идентификаторы **не зашиты в код**. Список лежит в
`/data/adb/vr_headset/devices.conf` и правится на ходу — демон перечитывает
его на каждой проверке:

```
3318:0436   # XREAL One Pro
```

Устройств можно перечислить несколько. Узнать идентификаторы:

```sh
vr-mode devices
```

Опознание идёт по USB, а не по DisplayPort, намеренно: в режиме гарнитуры
DP-коннектор гасится этим же модулем и рапортует `disconnected` — сенсор
на его основе ослеп бы сразу после первого срабатывания.

## Управление

```sh
vr-mode              # состояние: режим, очки, DP, звук, демон
vr-mode headset      # гарнитура: монитора нет
vr-mode monitor      # вернуть внешний дисплей
vr-mode devices      # список своих очков и что воткнуто сейчас
```

Команда лежит в `/data/adb/bin/vr-mode`. Режим хранится в `/data/adb/vr_mode`
и переживает перезагрузку.

## Совместимость с VR Display Mode

[VR Display Mode](https://github.com/davnozdu/vr-display-module) решает
обратную задачу — включает внешний дисплей в режиме рабочего стола. Режимы
взаимоисключающие: очки не могут быть одновременно монитором и гарнитурой.

Оба модуля читают один файл `/data/adb/vr_mode`. Пока в нём `headset`,
дисплейный модуль включать экран не должен. Если он этого ещё не умеет,
достаточно добавить в его демон проверку перед `try_enable`:

```sh
[ "$(cat /data/adb/vr_mode 2>/dev/null)" = "headset" ] && continue
```

Без такой проверки оба демона будут дёргать один и тот же коннектор:
дисплейный включать, этот — гасить. Видимого вреда не будет, монитор
в итоге останется скрытым, но при подключении возможна вспышка рабочего
стола на секунду-другую.

## Компаньон

Модуль ставит и обновляет приложение
[VR Companion](https://github.com/davnozdu/vr-companion) — переключение
режима плиткой в шторке, без терминала. Новая версия APK попадает в zip
при сборке модуля, поэтому приложение обновляется вместе с ним.

Если VR Companion уже стоял, установленный вручную из другого источника,
подписи не совпадут и установка из модуля не пройдёт — в логе будет прямо
об этом сказано. Удалите старую сборку, и модуль поставит свою.

Приложению нужен root: чтение `/data/adb` и вызов `vr-mode` иначе
недоступны. Выдайте разрешение один раз в KernelSU Manager → SuperUser.

## Установка

1. Скачайте zip из [Releases](https://github.com/davnozdu/vr-headset-mode/releases)
2. KernelSU Manager → Модули → Установить из хранилища
3. Перезагрузитесь

Дальше модуль обновляется сам через `updateJson`.

## Что модуль не трогает

- звук, микрофоны, камеру — они на USB 2.0 и от DisplayPort не зависят
- экран телефона, яркость, тачскрин
- список устройств при обновлении — `devices.conf` не перезаписывается

При удалении дисплей возвращается принудительно: иначе очки остались бы
немым монитором без способа включить его обратно.

## Почему возврат монитора идёт через `on`

Штатный способ вернуть автоопределение — записать в `status` слово `detect`.
Но после принудительного `off` физический линк DisplayPort разорван, и
переопрос ничего не находит: коннектор остаётся `disconnected`.

Поэтому `vr-mode monitor` сначала пробует `detect`, а если коннектор не
поднялся — форсирует `on`. Тогда ядро проводит модсет заново и дисплей
оживает без переподключения кабеля.

## Ограничение

Гашение не переживает переподключение кабеля само по себе — коннектор
возвращается в `connected`. Поэтому демон применяет режим на каждой
итерации опроса, а не только при изменении состояния. Задержка до двух
секунд после подключения — за это время рабочий стол может успеть мигнуть.
